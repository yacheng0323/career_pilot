# Milestone 1 — Job List + Detail Screen

## Goal

Deliver a working Flutter app with two screens (job list and job detail) powered by
local mock JSON data. No real API, no auth, no persistence — just a browsable,
navigable job board that proves out the full data → state → UI pipeline.

---

## Scope

| In scope | Out of scope |
|---|---|
| Job list screen (search bar + cards) | Login / auth |
| Job detail screen (title, company, description, skills) | Real crawler / API |
| Client-side keyword search filtering | Favorites / bookmarks |
| Riverpod state (`jobListProvider`) | Apply status tracking |
| GoRouter navigation (`/` and `/jobs/:id`) | AI summary / match score |
| Freezed `Job` model + `json_serializable` | Push notifications |
| `JobRepository` loading `assets/mock/jobs.json` | `SharedPreferences` persistence |
| `app_theme.dart` with seed color | `Dio` HTTP client |
| `ProviderScope` + `MaterialApp.router` setup | `mock_jobs.dart` file |
| | `core/utils/extensions.dart` |
| | Any M2 / M3 feature |

## Out of Scope

- Favorites / bookmarks (M2)
- Apply status tracking (M2)
- `SharedPreferences` (M2)
- `Dio` / real API (M2+)
- AI summary / match score (M3)
- Login / auth (never in MVP)
- Real job crawlers (never in MVP)
- Push notifications (never in MVP)
- `mock_jobs.dart` — data comes from JSON asset, not Dart constants
- `core/utils/extensions.dart` — not needed for M1
- Android / iOS native config changes

---

## Acceptance Criteria

1. App launches without runtime errors
2. Job list screen shows all 6 mock jobs
3. Search bar filters jobs by title or company (client-side)
4. Tapping a job card navigates to the detail screen
5. Detail screen shows: title, company, location, salary range, remote badge, description, skill chips
6. Back navigation works
7. `flutter analyze` reports **zero errors**
8. No real network calls, no auth, no persistence
